# Vite 8 and Major Dependency Upgrade — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move both Vite builds from 5.4.x to 8.x in staged steps, then delete the `overrides` block in the root `package.json` that currently forces `esbuild` and `rollup` past what Vite 5 supports.

**Architecture:** The upgrade is staged (5 → 6 → 7 → 8) rather than done in one jump, because each major has its own migration notes and the intermediate states are individually verifiable. Vite 8 replaces esbuild/rollup with Rolldown internally, which is what finally makes the `overrides` block unnecessary — that removal is the point of the whole exercise, not a side effect. Two further tasks pick up the remaining low-risk majors and re-enable Dependabot for the packages currently held back.

**Tech Stack:** npm workspaces, Vite (+ `@crxjs/vite-plugin` for the extension, `@vitejs/plugin-react` for the side panel), sass, Vitest, Playwright, TypeScript.

---

## Background: why this exists

The root `package.json` contains:

```json
"overrides": {
  "rollup": "4.55.1",
  "esbuild": "0.27.2"
}
```

Added in commit `becd607` ("Fix security issue"). Vite 5.4.21 declares `esbuild: ^0.21.3` (i.e. `< 0.22`), so the override forces it to run against a version it never claimed to support. It works at 0.27.2 by luck. It stopped working when Dependabot proposed 0.28.1: esbuild refuses to lower destructuring to the configured browser target, and `vite:esbuild-transpile` fails with 1 error for the extension build and 1045 for the side panel.

`esbuild` and `rollup` are therefore currently held in `.github/dependabot.yml`. This plan removes the need for that hold.

## Global Constraints

- **Do not use `fix:` or `feat:` in commit messages for this work.** They trigger a release and a Chrome Web Store publish. Every commit in this plan is `build:`, `chore(deps):` or `docs:`. See `docs/architecture/publishing.md`.
- **Never hand-edit the `version` field** in `package.json` or `packages/chrome-extension/public/manifest.json`. `release-please` owns them.
- **Generate TypeScript, not JavaScript**, for any new file.
- **No AI attribution in commit messages** — no `Co-Authored-By`, no "Generated by".
- Node **24** for local runs (Node 20.19+ / 22.12+ is Vite 7's floor; CI runs 22.x and 24.x).
- The extension's `minimum_chrome_version` is not set in the manifest, so Vite 7's default-target bump (Chrome 87 → 107) is acceptable: the Chrome Web Store serves current Chrome.

## Environment: what can and cannot be verified in a cloud sandbox

This plan is expected to run on a Linux agent. Three commands in this repo do **not** work there — none of them are needed to verify the upgrade, but an agent that runs them will report false failures.

| Command | Works on Linux? | Why |
| --- | --- | --- |
| `npm run test:fast` | ✅ yes | Vitest + jsdom only |
| `npm run build -w <package>` | ✅ yes | invokes `vite build` directly |
| `npm test` | ⚠️ partly | includes `build-smoke.slow.test.ts`, which **self-skips** when no PowerShell is present — so it passes without actually verifying the build |
| `npm run build:project` | ❌ no | the npm script hardcodes `powershell`, which exists only on Windows |
| `npm run test:e2e` | ❌ no | the Playwright spec uses `headless: false` and needs a display |

**Consequence:** after every dependency change, build both packages explicitly with the per-package commands below. Do not rely on `npm test` alone to catch a broken build.


## Task 2: Vite 6 → 7, including the sass legacy API

**Files:**
- Modify: `package.json`, `packages/chrome-extension/package.json`, `packages/sidePanel-import/package.json`
- Possibly modify: `packages/sidePanel-import/src/index.scss`

**Interfaces:**
- Consumes: Task 1's Vite 6 tree
- Produces: a tree on Vite 7 with no sass legacy-API usage

Vite 7 has two changes that affect this repo directly:

1. **Sass legacy API support is removed.** The current build already prints `DEPRECATION WARNING [legacy-js-api]: The legacy JS API is deprecated and will be removed in Dart Sass 2.0.0`. Under Vite 7 this is no longer a warning path.
2. **Default browser target** moves from `modules` to `baseline-widely-available` (Chrome 87 → 107, Edge 88 → 107, Firefox 78 → 104, Safari 14 → 16). Acceptable per Global Constraints.

- [ ] **Step 1: Bump Vite**

```bash
npm pkg set devDependencies.vite="^7.3.6"
npm pkg set devDependencies.vite="^7.3.6" -w @bexio-chrome-extension/chrome-extension
npm pkg set devDependencies.vite="^7.3.6" -w @bexio-chrome-extension/side-panel-import
npm install
```

- [ ] **Step 2: Run the verification snippet**

- [ ] **Step 3: If the side-panel build fails on sass**

The failure will name the legacy JS API or a removed sass feature. `packages/sidePanel-import/src/index.scss` is the only stylesheet. Fix forward rather than pinning sass back:
- Replace `@import` with `@use` / `@forward`.
- If a division is flagged, use `math.div()` with `@use "sass:math"`.

Re-run the verification snippet after the edit.

- [ ] **Step 4: Confirm the target change did not break the output**

```bash
node -e "
const s=require('fs').readFileSync('unpacked/index.ts.js','utf8');
console.log('bundle bytes:', s.length);
"
```

Expected: a number, i.e. the file exists and is non-empty. A hard failure here means the new target produced no output.

- [ ] **Step 5: Commit**

```bash
git add package.json packages/*/package.json package-lock.json packages/sidePanel-import/src/index.scss
git commit -m "build(deps): upgrade vite 6 -> 7 and move off the sass legacy API"
```

## Task 3: Vite 7 → 8, plugin-react 6, and removing the overrides

**Files:**
- Modify: `package.json` (Vite, **and** delete the `overrides` block), `packages/chrome-extension/package.json`, `packages/sidePanel-import/package.json`

**Interfaces:**
- Consumes: Task 2's Vite 7 tree
- Produces: a tree on Vite 8 with no `overrides` block

This is the task the plan exists for. Vite 8 merges Rolldown and no longer depends on esbuild at all, so the forced `esbuild` version becomes irrelevant.

`@vitejs/plugin-react@6` requires `vite: ^8.0.0` and must move in the same step — the currently installed 4.7.0 supports only Vite ≤ 7. Its other two peers (`@rolldown/plugin-babel`, `babel-plugin-react-compiler`) are optional; do not install them unless a build error asks for them.

- [ ] **Step 1: Bump Vite and plugin-react together**

```bash
npm pkg set devDependencies.vite="^8.1.5"
npm pkg set devDependencies.vite="^8.1.5" -w @bexio-chrome-extension/chrome-extension
npm pkg set devDependencies.vite="^8.1.5" -w @bexio-chrome-extension/side-panel-import
npm pkg set devDependencies."@vitejs/plugin-react"="^6.0.4" -w @bexio-chrome-extension/side-panel-import
npm install
```

- [ ] **Step 2: Run the verification snippet**

Expect this step to need work. Known risk areas, in likelihood order:
- `@crxjs/vite-plugin` under Rolldown. It declares `vite: ^8.0.0` support in its peers as of 2.7.1, but the extension config leans on `build.rollupOptions.output.{dir,chunkFileNames,entryFileNames}` and `assetsDir: ""` to keep content-script filenames hash-free. **If hashes reappear in `unpacked/`, the manifest's content-script paths break** — the verification snippet catches exactly this, since the referenced files will be missing.
- `manualChunks: undefined` in the side-panel config.

Fix forward in the config; do not pin Vite back.

- [ ] **Step 3: Delete the overrides block**

```bash
npm pkg delete overrides
npm install
```

- [ ] **Step 4: Confirm esbuild is gone or free**

```bash
npm ls esbuild --all || true
```

Expected: either esbuild is absent entirely, or it appears without the word `overridden`. If it still says `overridden`, the block was not fully removed.

- [ ] **Step 5: Run the verification snippet again**

- [ ] **Step 6: Commit**

```bash
git add package.json packages/*/package.json package-lock.json packages/*/vite.config.*
git commit -m "build(deps): upgrade vite 7 -> 8 and drop the esbuild/rollup overrides

Vite 8 merges Rolldown and no longer depends on esbuild, so the overrides
block added in becd607 to force esbuild past what vite 5 supported is no
longer needed. @vitejs/plugin-react moves to 6.x in the same step because it
requires vite ^8."
```

- [ ] `npm run test:e2e` — the Playwright extension smoke test (opens a visible Chromium window)
